# BrainBench (gbrain-evals): наш поиск на чужой линейке

**Даты прогонов:** 17 августа 2026. **Команда:** `python scripts/brainbench_run.py --corpus <путь>/gbrain-evals/eval/data/world-v1`

Это история в три акта: опубликованное число, его исправление вниз и
возврат — уже через фичи продукта, а не через подгонку. Все три состояния
воспроизводимы, ниже сказано как.

---

## 1. Что это за линейка

BrainBench — открытый бенчмарк памяти агентов из репозитория
[`garrytan/gbrain-evals`](https://github.com/garrytan/gbrain-evals) (MIT).
Корпус `world-v1`: 240 сгенерированных биографических страниц (люди,
компании, встречи, проекты). Золото — метаданные `_facts` каждой страницы,
из них раннер строит 145 реляционных запросов четырёх видов:
`Who attended / works at / invested in / advises <сущность>?`

Метрики — P@5 и R@5, макро-усреднение. Адаптеры золота не видят:
страницы проходят через `sanitizePage`, в запрос уходят только `id` и текст.

---

## 2. Результат: лесенка

Каждая строка отличается от предыдущей одной фичей — вклад виден отдельно.

| Вариант | P@5 | R@5 |
|---|---|---|
| наш BM25 без графа (контроль) | 0,161 | 0,597 |
| граф через RRF, без реляционного детектора | 0,240 | 0,806 |
| **дефолты прода: + реляционный детектор** | **0,310** | **0,893** |
| + CONFIDENT_GRAPH=on (флаг, в проде выключен) | 0,729 | 0,992 |

Их опубликованный скоркард на том же корпусе и тех же 145 запросах:

| Их адаптер | P@5 | R@5 |
|---|---|---|
| gbrain | 0,491 | 0,979 |
| vector-grep-rrf-fusion | 0,178 | 0,651 |
| grep-only | 0,171 | 0,624 |
| vector | 0,108 | 0,407 |

**В их собственном раннере** (не нашем порте) через тонкий адаптер-мост,
N=5 с перемешиванием порядка страниц, stddev 0.0 в обоих режимах:

| Режим | P@5 | R@5 | correct |
|---|---|---|---|
| дефолты прода | 31,6% | 90,0% | 229/261 |
| CONFIDENT_GRAPH=on | 72,9% | 99,1% | 257/261 |

Расхождение порт↔раннер — до ~1 пункта, задокументировано (контроль:
их grep-only у них 17,1/62,4, наш BM25-порт 16,1/59,7).

**Как это читать.** С дефолтами прода мы позади их графовой системы
(0,31 против 0,49) и впереди всех их не-графовых базисов. С включённым
флагом — впереди и их системы (72,9/99,1 против 49,1/97,9; 257 из 261
правильных против их 248), но флаг в проде выключен, пока режим не
проверен на наших данных, и это написано везде, где стоит число.

## 3. История числа (три акта)

**Акт 1 — 0,729 с подгонкой.** Первая версия адаптера содержала правила,
захардкоженные в скрипте бенчмарка: «вопрос с Who → только соседи-person»
и «перечислительный вопрос → только граф, без добора». Все 145 запросов
порождены четырьмя шаблонами «Who …?», золото всегда из людей — правила
были подогнаны под генератор вопросов. Абляции: без них 0,26–0,40, BM25
не добавлял ни сотой.

**Акт 2 — честные 0,240.** Правила сняты, адаптер приведён к проду как
есть, публикации исправлены вниз.

**Акт 3 — возврат через продукт.** Идеи оказались не подгонкой, а
пробелами продукта: «кто был на встрече в четверг» — ежедневный вопрос
наших пользователей, и на нём были те же три дыры. Правила вернулись как
фичи с русскими тестами и выключателями:

- `enumerative_detect` — реляционные вопросы без слова «все» («кто был на
  встрече», «кто отвечает за деплой», «who attended…»). Выключатель
  `RELATIONAL_DETECT`, default on (меняет только веса слияния, за
  родительским `ENUM_GRAPH_BOOST`).
- `answer_type` — тип ожидаемого ответа из вопросительного слова:
  «кто/who» → person, «когда/when» → time. Чистый модуль.
- `confident_graph` — полный структурный ответ без добора шума, когда
  вопрос реляционный, тип ответа известен и граф дал узлы этого типа.
  Выключатель `CONFIDENT_GRAPH`, **default OFF**: режим меняет состав
  выдачи, включим после проверки на своих данных.

Скрипт бенчмарка больше не содержит ни одного собственного правила
ранжирования — только вызовы этих модулей. Контракт закреплён тестами
(`tests/unit/test_brainbench_port.py`,
`tests/unit/test_relational_answer_type.py` — последний весь на русских
вопросах: чужой корпус не может наградить за «кто был на встрече»).

Попутно починен дефект детерминизма: соседи подавались в RRF в порядке
обхода множества, ранг зависел от рандомизации хешей (прогон плавал
0,727…0,730). Теперь соседи сортируются по слагу.

## 4. Границы честности

- Это наш порт их харнесса; их настоящий раннер подключён отдельно
  (мост в `integrations/gbrain-evals/`), числа обоих напечатаны выше.
- Векторного канала в прогоне нет (нет модели эмбеддингов) — у gbrain
  он есть. Играет против нас, размер эффекта не измерен.
- Правила писались от живых вопросов к продукту — он двуязычный
  (русский и английский), русские тесты стоят первыми, потому что
  по-русски мы проверяем сами. Этот корпус — **валидация, а не источник**. Но риск остаётся: все 145 вопросов
  корпуса однотипны («Who …?» → всегда person), на разнообразных
  вопросах преимущество уверенного режима будет меньше. Подтверждение —
  только прогон на наших русских наборах без регрессии; до этого
  CONFIDENT_GRAPH выключен.
- Прогон покрывает Cat 1–2 (точность/полнота ретрива) — как и их
  скоркард, с которым сравниваемся.
- На этом корпусе рёбра графа безымянные (из markdown-ссылок), продовое
  типизированное извлечение не запускается. «Кто инвестировал в X» и
  «кто участвовал в X» различаются у нас только типом узла, не типом
  ребра — у gbrain типы рёбер есть.

## 5. Как воспроизвести

```sh
git clone --depth 1 https://github.com/garrytan/gbrain-evals /tmp/ge
# лесенка целиком (все четыре строки)
python scripts/brainbench_run.py --corpus /tmp/ge/eval/data/world-v1
```

Их раннер (мост, см. `integrations/gbrain-evals/README.md`):

```sh
TESSENT_REPO=<этот репозиторий> bun eval/runner/multi-adapter.ts --adapter=tessent-brain
CONFIDENT_GRAPH=on TESSENT_REPO=… bun eval/runner/multi-adapter.ts --adapter=tessent-brain
```

Акт 1 (снятый подогнанный вариант) воспроизводится из истории git:
коммит `fb6db2d` содержит исходную версию скрипта.

## 6. Что дальше

1. Прогнать реляционный детектор и CONFIDENT_GRAPH на наших русских
   наборах (счётные вопросы из BENCHMARK_COUNTING, LongMemEval
   multi-session) — без регрессии → включать флаг по умолчанию.
2. Типизированное извлечение над их корпусом (ключи моделей в окружении
   есть) — первый прогон, где систему меряют целиком, а не поисковую
   треть.
