Новая проверка — **H. Граница клиентских звонков**: ни один из семи клиентских звонков (шесть с Титаном плюс Северный Дом) не должен содержать внутренние факты компании — решение о найме, наблюдение о состоянии Соколовой, сумму раунда, новую вилку зарплаты. ## Главная находка этого среза — не в корпусе, а в паттерне, который я сам написал неверно дважды подряд

Задумал новую проверку H, взял для неё «внутренний» паттерн найма из уже проверенного LF-05 (`наня(ть|ли)|найм|...`) — и допустил сразу два независимых промаха.

**Первый: скопировал не целиком.** В CB-01 попала только половина паттерна LF-05 — без ветки `менеджер.{0,15}продаж`, которая единственная реально работала (см. ниже). Мутационный тест с внедрённой фразой «менеджеров нанимаете» прошёл как ЗЕЛЁНЫЙ — утечка не была поймана, хотя `grep -c` подтвердил, что мутация действительно попала в файл.

**Второй, глубже: сам паттерн `найм` был мёртв с рождения.** Слово «наём» пишется через **ё**, а не через **й** — «найм» и «наём» визуально похожи, но это разные буквы и разная строка. За всё время, что LF-05 отчитывался зелёным (срезы 2–4), его на самом деле держала одна-единственная ветка — `менеджер.{0,15}продаж`, точное совпадение с формулировкой ruk-07. Ветка `найм` не сработала ни разу, потому что не могла сработать в принципе.

Попытка исправить оба промаха сразу дала третий урок. Расширил паттерн до `наня(ть|л|ла|ли)|наним(а|ать)|наём|наем` — грамматически более полный охват глагола «нанимать» — и прогнал по всем 20 транскриптам **до** внесения в ground truth. Результат: пять ложных срабатываний. Три — банальная проблема границ строки: «наём» без границ слова совпадает как подстрока внутри «начин**аем**» и «не зн**аем**» в четырёх разных встречах. Но четвёртое — не баг паттерна, а реальный найденный факт: в `ruk-06` Гелин спрашивает Ватулина «Нанимать?» про ресурс внедрения, получает «Пока нет» — **это другое, легитимное обсуждение найма**, не имеющее отношения к решению о менеджерах по продажам из `ruk-07`. Более широкий паттерн, задуманный «поймать любой найм», на самом деле смешивает два независимых сюжета корпуса.

Вывод, ради которого стоило дважды ошибиться: **для этой проверки правильный инструмент — узкий, тематический паттерн, а не грамматически полный.** `менеджер.{0,15}продаж` работал с самого начала не потому, что был случайно удачным, а потому что он специфичен ровно к тому факту, который призван защищать. Ширина покрытия и точность цели — разные оси, и для проверки типа «эта конкретная внутренняя тайна не должна протечь» точность важнее полноты. Паттерн в LF-05 и CB-01 возвращён к узкой форме; мутация с «менеджеров по продажам нанимаете» в клиентском звонке теперь ловится корректно.

## Симметрия, которую не планировал, но она сложилась сама

Обе стороны API-блокера застряли в собственном процессе, не видя чужого целиком: Царёв внутри знает только «обещали в январе, не дали» (sink-03); Волков объясняет, что сам подал заявку в январе и она «где-то между вторым и третьим согласованием» (klient-titan-3). Ни один внутренний документ Гелиона не связывает эти два факта — компания не знает, что клиент тоже застрял, а не просто тянет время. Хороший диагностический вопрос для демо: попросит ли система связать «наш риск API» (arc 4) с «его объяснение блокера» (arc 14) в единую картину, или покажет их как два разрозненных факта.

## Запуск

```bash
pip install pyyaml
python3 scripts/gen_data.py        # без изменений: CRM + финтаблица из ground truth
python3 scripts/validate_corpus.py # теперь 7 именованных проверок (A/B/C/E/G/H) + 2 справочных (D/F)
```

**Короткий путь — корпус лежит уже извлечённым.** В `extracted/` — полный
выход конвейера по каждой встрече (решения, задачи, участники, KPI,
профили), в `snapshot/` — готовое zero-infra-хранилище (граф + векторный
индекс с посчитанными эмбеддингами). Два способа:

```bash
# залить извлечения в ваше хранилище — без LLM-вызовов и без ключа:
python scripts/seed_demo.py --corpus demo/gelion

# или мгновенно: скопировать готовое хранилище и поднять API на нём
mkdir -p data && cp demo/gelion/snapshot/*.json data/
USE_NETWORKX=true USE_QDRANT=false python -m backend.main
```

Оба — артефакты сборки: при изменении извлекателей перегенерируйте их
(нужен ключ модели; env-переменные принудительно выбирают файловое
хранилище, чтобы снапшот лёг в `snapshot/` независимо от того, на чём
работает ваш бекенд):

```bash
USE_NETWORKX=true USE_QDRANT=false \
GRAPH_STORAGE_PATH=demo/gelion/snapshot/knowledge_graph.json \
VECTOR_STORAGE_PATH=demo/gelion/snapshot/vector_index.json \
python scripts/ingest_data.py --source files --target demo/gelion/transcripts \
  --group public --dump-extractions demo/gelion/extracted
```

Источник истины — `transcripts/` + `ground-truth.yaml`.
